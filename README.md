# groomer-assistant

Веб-приложение Pretty Dogs для рабочего процесса грумера: календарь и смены, очередь, карточки питомцев, карта стрижки, фото, история визитов и учёт заработка.

## Веб-приложение

Приложение открывается в обычном браузере по корневому адресу Worker `/` или `/app`. Оно больше не требует запуска через Telegram и работает с D1 и R2 напрямую.

- **Главное** — очередь на сегодня, статусы визитов, заработок и создание записей.
- **Календарь** — рабочие дни, часы смен, записи на выбранную дату, создание, редактирование и перенос будущих записей.
- **Питомцы** — карточки, данные питомца, главное фото, карта стрижки и фото-примеры.
- **Визиты** — история, выполненные услуги, длительность и фото после визита.
- **Доход** — итоги за день, месяц и половины месяца.

## Первичная настройка

### 1. Подключить хранилище фотографий

Приложение использует Cloudflare R2, чтобы фотографии хранились независимо от Telegram.

1. В Cloudflare открой **R2 Object Storage** и создай bucket с именем `pretty-dogs-photos`.
2. В конфигурации `wrangler.toml` уже добавлена привязка `PHOTOS` к этому bucket.
3. Опубликуй Worker после того, как bucket создан.

D1 остаётся основной базой данных. Карточки, записи, история услуг и доход сохраняются там; бинарные файлы фотографий — в R2.

### 2. Настроить пароль

1. Открой Cloudflare → **Workers & Pages** → `groomer-assistant` → **Settings** → **Variables and Secrets**.
2. Добавь Secret с именем `WEB_APP_PASSWORD`.
3. Задай длинный уникальный пароль не менее 16 символов. Не добавляй его в GitHub или `wrangler.toml`.
4. Убедись, что Worker опубликован.

Веб-сессия действует 30 дней. Вход выполняется в обычном браузере; Telegram SDK для авторизации не используется.

## Безопасный переход с Telegram-бота

**Не удаляй бота и не убирай секрет `BOT_TOKEN`, пока не перенесены старые фотографии.** Ранее фотографии хранились через Telegram file ID, и после отзыва токена эти файлы нельзя будет скачать по старым идентификаторам.

1. Создай R2 bucket `pretty-dogs-photos`, настрой `WEB_APP_PASSWORD` и опубликуй актуальный Worker, пока `BOT_TOKEN` ещё существует и действителен.
2. Открой приложение по адресу Worker в обычном браузере и войди с веб-паролем.
3. На главной странице появится блок **«Перенос архива фотографий»**, если в базе есть фотографии, привязанные к Telegram. Нажимай **«Перенести фотографии»** / **«Продолжить перенос»**, пока перенос не закончится. Каждый запуск переносит следующую порцию.
4. Убедись, что блок сообщает о переносе архива и вручную проверь главное фото питомца, фото-примеры и фото после визита.
5. Проверь создание записи, начало и завершение визита, сохранение услуг и загрузку новых фото в R2.
6. Только после этого удали Secret `BOT_TOKEN` из настроек Worker и, если нужно, удали самого бота через BotFather.

Перенос использует Telegram API временно — только для чтения старых изображений. Обычная работа веб-приложения после переноса от токена Telegram не зависит. Если старый токен уже отозван и фото ещё не перенесены, прежние фотографии могут быть недоступны; данные карточек и учёта в D1 от этого не удаляются.

## Файлы и ресурсы

- Worker entry point: `src/index.js`
- HTML/CSS/JS веб-приложения: `src/web-app.js`
- D1 binding: `DB`
- R2 binding: `PHOTOS` → bucket `pretty-dogs-photos`

Планировщик Telegram-напоминаний отключён. Секрет `WEB_APP_PASSWORD` должен храниться в Cloudflare Secrets, не в репозитории.
